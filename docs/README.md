## 읽기와 갱신 순서

공통 지침과 프로젝트 정의를 확인한 뒤 UI 작업은 프론트 안내, 서버 작업은 백엔드 안내, 환경 작업은 개발·인프라 안내를 읽습니다. 서비스 사이 동작을 바꾸면 계약과 설계, 재구성 품질을 다루면 관련 실험 기록을 추가로 확인합니다. 매번 전체 문서를 읽지 않습니다.

상세 내용은 위 표의 담당 문서 한 곳에서 갱신합니다. 다른 문서와 README에는 짧은 설명과 링크만 둡니다. 구현 상태는 개발 안내, 과거 선택 이유는 결정 기록으로 구분합니다. 문서와 코드가 다르면 요구사항과 실제 동작의 차이를 확인하고 관련 문서를 바로잡습니다.

## 기록 기준

- **확정:** 사용자 지정 또는 채택 근거가 있는 결정. 날짜와 근거를 적습니다.
- **제안:** 검토할 선택지. 채택된 결정처럼 적용하지 않습니다.
- **사용자/팀원 보고:** 전달받은 결과. 직접 실행·확인한 결과와 구분합니다.
- **직접 확인:** 실행 환경·입력·방법·결과가 확인된 내용입니다.
- **미확정/미확인:** 결정을 하지 않았거나 증거를 확인하지 못한 내용입니다.

기술 내용이 바뀌면 해당 문서를 갱신하고 중요한 결정은 별도 기록합니다. 대화 전체를 복사하지 않습니다. Notion은 회의·일정·담당자·토론, Git 문서는 실행·설계·재현 정보의 기준으로 관리합니다. `.ai-context/`는 선택적인 개인 자료이며 공통 개발의 필수 의존성이 아닙니다.
