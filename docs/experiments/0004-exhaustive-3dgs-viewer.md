# 0004 — 전수 매칭 모델로 3DGS 학습 및 실내 뷰어 확인

- 날짜: 2026-11-22
- 작성자/실행자: skdks2525 / skdks2525
- 상태: 완료 (로컬 PLY 생성 및 뷰어 표시)
- 증거: 직접 실행. 학습 함수 실행 시간, PLY 헤더와 파일 크기, Edge의 뷰어 첫 화면과 별도 시점 렌더링을 확인했다.

## 목적과 판정 기준

[실험 0002](0002-colmap-registration-criteria.md)의 전수 매칭 결과로 Worker의 학습 함수가 20,000스텝을 마치고 유효한 3DGS PLY를 내보내는지 확인한다. 파일 생성은 Worker의 가우시안 속성·크기 검사 통과로, 웹 표시는 내보낸 모델을 바탕으로 만든 로컬 HTML을 브라우저에서 열어 실내 장면이 보이는지로 판정한다. 시각 품질은 촬영 시점별로 관찰한다.

## 입력과 재현 환경

| 항목 | 값 |
| --- | --- |
| 영상 입력 | 0002와 같은 실내 영상에서 6 FPS로 추출한 JPG 495장, 1080×1920 |
| 카메라 추정 결과 | COLMAP 3.11.1 GPU 전수 매칭 모델 `sparse/0`. 등록 사진 283장(57.2%), 초기 희소 3D 점 17,275개 |
| 학습 환경 | Windows, RTX 3070 Ti 8GB, PyTorch 2.4.0+cu124, Nerfstudio 1.1.5 |
| 학습 설정 | Splatfacto, 20,000스텝, 이미지 축소 계수 1 |
| 결과 확인 도구 | PlayCanvas SplatTransform 3.11.1, Microsoft Edge |

## 실행 방법

1. 기존 JPG 폴더와 전수 매칭 모델 폴더를 [Worker의 학습 함수](../../gpu-worker/src/bangpick_worker/train_3dgs.py)에 직접 전달했다. 아래는 당시 호출에서 로컬 경로를 변수로 표시한 예다.

   ```python
   ply = train_3dgs(images_dir, experiment_dir / "sparse" / "0", experiment_dir / "3dgs")
   ```

2. 함수가 `ns-train splatfacto`로 학습한 뒤 `ns-export gaussian-splat`으로 `3dgs/room.ply`를 생성했다. Worker가 헤더의 필수 가우시안 속성과 실제 데이터 크기를 검사했다.
3. 등록된 72번 프레임의 카메라 위치와 방향을 시작 시점으로 설정해 단일 파일 뷰어 `room-tour.html`을 만들고 Edge에서 열었다. 353번 프레임의 카메라에서도 같은 PLY를 렌더링했다.

## 해석·한계·다음 검증

283장이 등록된 모델로 PLY를 생성하고 브라우저에 표시할 수 있었다. 동일한 모델에서도 시점별로 선명도가 달랐다. 두 촬영 시점의 관찰만으로 방과 복도 사이 전체 이동 경로의 품질이나 공간 치수 정확성을 평가하기는 어렵다.

[실험 0003](0003-worker-queue-local-video.md)의 큐 실행은 순차 매칭 등록 기준 미달로 중단됐다. 이번 실행은 전수 매칭 모델을 학습 함수에 직접 전달했으므로, 다음 통합 검증에서는 같은 큐 작업 안에서 전수 매칭·학습·PLY 업로드·완료 보고까지 이어지는지 확인한다.
