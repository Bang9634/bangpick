# 0002 — COLMAP 순차·전수 매칭에 따른 사진 등록률과 처리 시간

- 작성자/실행자: skdks2525 / skdks2525
- 상태: 완료 (대표 영상 1건의 매칭 방식 비교)
- 증거: 직접 실행. COLMAP 로그, 매칭 데이터베이스, 희소 모델의 등록 이미지 목록을 확인했다.

## 목적과 판정 기준

현재 Worker는 유효한 COLMAP 모델 중 등록 사진이 가장 많은 모델을 선택한다. 이 모델에 **100장 이상**이 등록되고, 등록 장수가 **전체 입력 JPG의 20% 이상**일 때 3DGS 학습을 시작한다. 기존 50%에서 20%로 낮춰 더 다양한 등록률의 결과를 비교한다. **두 수치는 임시값이며, 실내 투어 품질을 판별하는 기준으로서 타당한지는 실험으로 검증해야 한다.**

방·문턱·복도처럼 영상에 담긴 구간을 결과에서도 식별할 수 있는지 확인한다. 두 수치를 통과했어도 공간이 누락된 사례와, 기준에 미달했어도 공간이 재현된 사례를 비교해 장수와 비율을 유지하거나 조정할 근거를 남긴다.

## 입력과 재현 환경

| 항목 | 실행 조건 |
| --- | --- |
| 입력 | 실내 재촬영 영상 1건에서 6 FPS로 추출한 JPG 495장, 1080×1920 |
| 실행 환경 | Windows, NVIDIA GeForce RTX 3070 Ti 8GB, COLMAP 3.11.1 CUDA 빌드 |
| 비교 조건 | 단일 카메라, GPU SIFT 매칭, 매칭 상한 12,000. 두 방식 모두 동일한 특징점과 기본 mapper 설정 사용 |
| 산출물 식별자 | 로컬 실험 폴더 `matching-20261122-034057`. 순차 결과는 `gpu.db`와 `mapper-diag-1795286952/`, 전수 결과는 `exhaustive-1795287148/` |

## 실행 방법

1. 동일한 JPG 목록으로 `feature_extractor`를 한 번 실행했다(`--ImageReader.single_camera 1`). 생성된 `features.db`를 방식별로 복사했다.
2. 각 복사본에 `sequential_matcher` 또는 `exhaustive_matcher`를 실행했다. 두 명령 모두 `--SiftMatching.use_gpu 1 --SiftMatching.max_num_matches 12000`을 사용했다.
3. 방식별 DB와 동일한 이미지 폴더로 `mapper`를 실행해 별도 출력 폴더에 모델을 저장했다. 모델별 등록 장수를 기록하고 가장 큰 모델로 학습 시작 기준을 판정했다.
4. DB의 `two_view_geometries`에서 검증된 대응점이 한 개 이상인 사진 쌍을 셌다. 입력 목록과 선택 모델의 `images.bin` 파일명을 촬영 순서로 대조해 가장 긴 연속 미등록 구간을 구했다.

## 해석·한계·다음 검증

이 영상에서 전수 매칭은 순차 매칭보다 약 61초 더 걸렸고 가장 큰 모델에 263장을 더 등록했다. 이번 사례는 매칭 방식을 바꿔 재시도할 근거가 된다. 50%와 20%에서 통과 여부가 동일했으므로 두 임시 기준 중 어느 쪽이 투어 품질을 더 잘 판별하는지는 다른 영상으로 검증해야 한다.

별도 Worker 큐 실행에서는 순차 매칭으로 선택된 모델에 2장이 등록됐다. 위 표의 순차 20장은 보존된 매칭 DB로 mapper를 별도 실행했을 때의 최대값이다. 연속 미등록 구간에서 실제 공간이 누락됐는지는 원본 영상의 해당 시간대와 투어를 대조해 확인한다.

**연속 미등록 프레임 수 제한은 확장 후보**다. 전체 등록률이 비슷한 영상에서도 미등록 프레임이 방 사이 이동 구간에 몰릴 때 공간 누락이 더 자주 관찰되는지 확인한다. 같은 장수도 추출 FPS와 촬영 속도에 따라 시간과 이동 거리가 달라지므로 해당 구간의 영상을 함께 검토한다.

긴 미등록 구간에서도 투어가 양호한 사례까지 검토한 뒤, 경고만 표시할지 또는 학습 중단 조건에 포함할지 결정한다. 허용할 최대 연속 장수와 100장·20% 기준의 조정값은 미정이며, 선정한 기준은 다른 영상에서도 다시 평가한다.

**사용자 승인 후 재시도**는 확장 후보다. 기준 미달 시 사용자에게 등록 장수·비율과 중단 이유를 보여주고 재시도 여부를 묻는다. 사용자가 순차 매칭 또는 전수 매칭을 선택해 승인하면 백엔드가 해당 방식으로 큐에 새 시도를 등록한다. Worker는 COLMAP을 다시 실행하고 같은 등록 기준을 통과한 경우에만 3DGS 학습을 시작한다.
