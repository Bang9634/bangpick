# 프로젝트 정의

기준일: 2026-11-12. 근거: 사용자가 제공한 인수인계, 프로젝트명 지정, 팀원 실험 공유 및 웹 투어 요구.

## 목적

**bangpick**은 3D Gaussian Splatting 기반 실내 공간 재구성 및 실측 정보 연동 가상 부동산 투어 시스템입니다. 학부 캡스톤디자인 I·II 두 학기에 걸쳐 컴퓨터 비전·3D 그래픽스·웹서비스를 통합하고 결과를 평가합니다.

3인 팀이 담당 영역을 중심으로 상호 지원하며 개발합니다. 역할은 [팀 구성](team.md), 공개 범위와 Git 작업 흐름은 [협업 안내](../CONTRIBUTING.md)를 따릅니다.

## 사용자 흐름

매물 등록자는 기본 매물 정보와 직접 촬영하거나 이용 동의를 받은 사진·영상을 등록합니다. 시스템은 카메라 추정·재구성·웹 제공용 처리를 수행하고, 등록자는 결과를 검토한 뒤 공개합니다. 방문자는 지도·검색에서 매물을 선택하고 상세 페이지의 투어를 엽니다.

WASD·마우스 탐색과 품질을 확인한 영역 안의 이동 제한이 요구됩니다. 위 흐름은 요구사항이며 이 저장소에 구현된 기능 목록은 아닙니다.

백엔드의 권한·작업 상태 관리와 오브젝트 스토리지, 비동기 Worker 처리를 분리하는 구조를 채택했습니다. 서비스 통합 개발 초기부터 오브젝트 스토리지를 사용합니다. 구체적인 등록·업로드·검수·조회 흐름은 [결정 0003](decisions/0003-storage-and-worker-flow.md)을 따릅니다.

일반 매물의 원본 영상은 검수 승인 후 7일 보관하고 삭제합니다. 최종 투어 결과와 별도 동의받아 지정한 평가 데이터는 구분합니다. 자세한 범위는 [원본 보관 정책](decisions/0004-source-video-retention.md)을 따릅니다.

## 범위

- 1학기 방향: 매물 플랫폼, 사진·영상 처리, 3D 재구성, 비동기 작업 관리, 웹 투어 통합.
- 2학기 방향: 실측값·평면도 연동, 좌표 정렬과 스케일 보정, 독립 측정과 비교, 불일치·미검증 항목 표시 및 성능 개선.
- 초기 필수 범위에서 제외: 계약·결제, 전국 매물 자동 연동, 정확한 가구 배치, 완전 자동 평면도와 모든 치수 복원, 이미지 조작 완전 판정.
- LiDAR·RoomPlan은 장비·기간에 따라 검토하는 후보입니다.

## 핵심 용어와 제약

| 용어 | 의미 |
| --- | --- |
| 시각 모델 | 가우시안으로 표현한 장면. 벽의 물리적 충돌이나 정확한 치수를 자동 제공하지 않음 |
| 충돌 데이터 | 통과를 막는 별도 기하·voxel 정보 |
| 이동 가능 영역 | 촬영 범위·품질 확인·경계를 고려해 사용자에게 허용하는 영역 |
| 실측 정보 | 외부 기준으로 측정한 값. 스케일 보정용과 평가용을 구분 |
| 재구성 작업 | 업로드부터 전처리·카메라 추정·학습·내보내기까지 추적하는 처리 |

시각적 품질과 기하 정확성을 동일시하지 않습니다. 장면 정리·압축·이동 제한은 각기 다른 역할입니다. 평면도와 모델이 일치해도 실제 공간의 진위를 보증하지 않습니다. 재구성 실패와 부분 미촬영, 검증 불가를 정상 결과로 숨기지 않습니다.

## 기본 기술 선택

2026-11-12 사용자 답변 기준이며 상세 구성 제안과 구분합니다.

| 영역 | 사용자 기본 선택 |
| --- | --- |
| 프론트엔드 | React + TypeScript + Vite |
| 백엔드 | Java 21 + Spring Boot 4.1.2 + Maven |
| 데이터베이스 | MySQL, 로컬 컨테이너는 8.4 |
| 배포 패키징 | Docker |
| 오브젝트 스토리지 | Oracle Cloud Infrastructure Object Storage 우선 후보. 계정별 무료 한도·브라우저 연동 검증 후 선정 |
| 지도 | NAVER Maps 우선 검토, Kakao Maps도 후보 |

프론트는 사용자 선택으로 TypeScript·Vite를 사용합니다. 백엔드는 사용자가 Maven에 익숙하다는 의견을 반영해 Maven으로 생성했습니다. Python Worker 초기 패키지와 Docker 실행 진입점은 만들었으며 실제 GPU 학습 도구는 팀 실험을 기준으로 별도 확정합니다. 지도 제공자는 API 연동 전에 결정합니다.

학습 장비는 초기에는 팀에서 사용 가능한 GPU PC를 필요할 때 가동하고, 추후 클라우드 등 다른 GPU 환경을 확보하는 방향입니다 (2026-11-12 사용자 답변). 특정 장비의 상시 가동을 전제로 하지 않습니다. 운영 구조 제안은 [개발 안내](development.md)를 따릅니다.

## 현재 증거와 다음 검증

팀원은 원룸 영상 학습과 내부 탐색에 성공했다고 보고했습니다. 촬영 범위 밖에서는 뭉개짐이 나타납니다. [공유된 실험 기록](experiments/0001-room-reconstruction.md)에 환경과 한계를 정리했습니다. 원본 모델·로그와 웹 성능은 아직 직접 확인하지 않았습니다.

현재 다음 검증 대상은 기존 모델의 내보내기·정리·이동 제한·웹 제공입니다. 위 기본 기술 선택을 기준으로 상세 프레임워크·웹 뷰어·운영 환경을 정합니다. MVP 우선순위와 성능 기준은 검증 결과를 바탕으로 구체화합니다. 시작 화면·백엔드 상태 확인·Worker 실행 진입점과 로컬 Docker 구성은 생성했습니다. 서비스 기능과 실제 GPU 학습·OCI 연동·운영 배포는 아직 없습니다.
