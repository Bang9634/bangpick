# 개발 환경과 실행 안내

## 현재 구현 상태

| 영역 | 현재 코드에 포함된 기능 |
| --- | --- |
| 프론트엔드 | 영상 전송·작업 조회 함수, Spark·Three.js 기반 PLY 뷰어. 기본 화면은 프로젝트 소개 |
| 백엔드 | 영상·PLY 전송 권한 발급·회수, 객체 크기 확인, MySQL 작업 상태와 결과 키 관리, 대기 작업 선택·점유, 만료 작업 수동 복구 API |
| GPU Worker | 대기 작업의 단건·반복 처리, 지정 작업 수동 전송, 로컬 처리 명령 감시·자동 heartbeat |
| 로컬 인프라 | 웹·백엔드·MySQL Compose, Worker 별도 Compose와 GPU 할당 설정 |

영상·PLY 전송 API는 기본으로 꺼져 있습니다. 개발 환경에서는 브라우저와 Worker에 서로 다른 개발 토큰을 사용합니다. 설정과 API 형식은 [백엔드 실행 안내](../backend/README.md#oci-파일-전송-개발-환경)와 [서비스 간 계약](../contracts/README.md#영상ply-전송)에 있습니다.

## 필요한 환경과 의존성

| 구성 | 로컬 실행 환경 | 실행 안내 |
| --- | --- | --- |
| 프론트엔드 | React·TypeScript·Vite, Node.js 24 권장 | [프론트 설치·실행](../frontend/README.md) |
| 백엔드 | Java 21·Spring Boot·Maven Wrapper | [백엔드 실행·DB 연결](../backend/README.md) |
| Worker | Python 3.11 이상 | [Worker 전송 명령](../gpu-worker/README.md) |
| 컨테이너 | Docker·Compose v2.30 이상, MySQL 8.4 | [Docker와 GPU 설정](../infra/README.md) |

컨테이너로만 실행할 때 호스트에 Node.js·Java·Python을 모두 설치할 필요는 없습니다. Worker 전송 테스트에는 GPU가 필요하지 않습니다. 실제 학습 환경은 [재구성 실험](experiments/0001-room-reconstruction.md)에 기록합니다.

## 영상·PLY 전송 검증

2026-11-16 개발 환경에서 확인한 내용입니다.

- **팀원 확인:** 브라우저에서 원본 영상을 OCI에 올리고 Worker로 내려받았습니다. Worker로 테스트용 3DGS PLY를 올린 뒤 브라우저에서 내려받아 렌더링했습니다. 이 검증에 사용한 화면은 기본 앱에서 제거했습니다.
- **직접 확인:** 개발 버킷의 객체별 업로드 URL 발급·회수, 로컬 MySQL의 기존 `RESULT_READY` 작업 조회. 백엔드 테스트 6개, Worker 테스트 3개, 프론트 lint·빌드 통과.
- **검증 범위:** 테스트 PLY의 전송과 렌더링. 원룸 모델의 재구성 품질·이동 제한·성능과 운영 배포 결과는 이 기록에 포함하지 않습니다.

초기 Docker·DB 구성의 배경은 [초기 개발 환경 결정](decisions/0005-monorepo-bootstrap.md)에 있습니다. 실제 설정값은 Git에서 제외된 `.env`에 두고 공유할 변수 이름은 [`.env.example`](../.env.example)에서 관리합니다.

2026-11-18 대기열 선택·입력 실패 검증: H2 기반 백엔드 테스트에서 가장 오래된 실행 가능 작업 선택, 미래 `available_at` 제외, 동시 요청의 중복 점유 방지, V2 이전 대기 행의 시각 미상값 보충, 점유 ID별 실패 보고와 최대 3회 시도를 확인했습니다. Worker의 `download-next` 명령은 `claim-next`를 한 번 호출하고 점유 ID 저장 후 원본 다운로드를 수행하며 입력 실패를 보고합니다. 백엔드 테스트 11개, Python 단위 테스트 8개, 프론트 lint·빌드가 통과했습니다. 실제 MySQL 동시성은 검증하지 않았고, 지속 실행·GPU 단일 실행 제한·응답 없이 중단된 작업의 만료 점유 복구도 아직 구현되지 않았습니다.

2026-11-19 heartbeat 검증: H2 기반 백엔드 테스트에서 현재 점유자만 만료 시각을 갱신하고 만료·완료·실패한 점유는 거부함을 확인했습니다. Worker의 단발 `heartbeat` 명령은 저장된 점유 ID를 사용합니다. 백엔드 테스트 12개, Python 단위 테스트 10개가 통과했습니다. 주기적 호출과 중단된 실행의 복구는 아직 구현되지 않았습니다.

2026-11-19 로컬 명령 감시 검증: Worker의 `run-process`가 시작 전과 실행 중 heartbeat를 보내고, 같은 작업 디렉터리의 두 번째 실행을 거부하며, heartbeat 실패 시 직접 실행한 프로세스를 종료하도록 Python 단위 테스트 16개를 통과했습니다. 실제 CLI 인자 해석도 확인했습니다. 당시 GPU 학습 실행, 호스트 간 동시 실행 제한, 실패 상태 보고, 만료 작업 복구는 구현되지 않았습니다.

2026-11-19 처리 실패 보고 검증: 백엔드 `processing-failed`가 현재 점유 ID의 처리 실패를 `QUEUED` 또는 `FAILED`로 전환하고, 이전 점유·만료 점유·결과 업로드 후 실패 보고를 거부하는 것을 H2 기반 테스트로 확인했습니다. Worker는 처리 명령의 시작 실패·비정상 종료를 보고하고 같은 점유 ID로 보고를 재시도할 수 있습니다. 보고 응답이 없으면 점유 파일을 보존하고, heartbeat 실패 시에는 자동 재대기시키지 않습니다. 백엔드 테스트 14개, Python 단위 테스트 20개가 통과했습니다. 실제 MySQL·GPU 처리, 호스트 간 동시 실행 제한, 응답 없이 중단된 작업의 복구는 검증하거나 구현하지 않았습니다.

2026-11-19 만료 점유 재점유 차단 검증: 지정 `claim`이 만료된 `PROCESSING` 작업의 새 점유를 거부하고 기존 점유 ID·시도 횟수·결과 키를 유지하는 것을 H2 기반 백엔드 테스트로 확인했습니다. `mvnw verify`에서 백엔드 테스트 14개가 통과했습니다. 이전 실행 종료 확인과 안전한 복구 경로는 아직 구현되지 않아 해당 작업은 `PROCESSING`에 남습니다.

2026-11-19 수동 복구 검증: 별도 복구 토큰과 이전 실행 중단 확인이 있을 때만 만료된 점유를 `QUEUED` 또는 `FAILED`로 전환하도록 구현했습니다. H2 기반 테스트에서 활성·다른 점유의 거부, 중복 요청, 결과 쓰기 권한 회수와 결과 키 초기화, 최대 3회 시도를 확인했고 `mvnw verify`에서 백엔드 테스트 18개가 통과했습니다. 백엔드는 운영자의 중단 확인 선언을 검사하지만 GPU 실행 종료를 직접 검증하지 않습니다. 실제 MySQL·OCI·GPU 연동에서 이 복구 경로를 실행한 결과는 아직 없습니다.

2026-11-19 Worker 일괄 처리 명령 검증: `process-next`가 같은 작업 디렉터리의 잠금을 점유 전에 얻고, 가짜 백엔드와 로컬 처리 명령으로 원본 다운로드부터 점유 ID별 PLY 업로드·완료 보고까지 실행하는 것을 확인했습니다. 대기 작업 없음, 처리 실패, 결과 누락, 업로드·완료 보고 오류와 `--` 뒤 명령 전달도 Python 테스트로 확인했습니다. Worker 테스트 30개와 CLI 도움말 확인이 통과했습니다. 실제 OCI 전송·GPU 학습·웹 렌더링 및 호스트 간 GPU 동시 실행 제한은 이번 검증 범위에 포함되지 않았습니다.

2026-11-19 로컬 점유 기록 실패 검증: `claim-next` 응답 뒤 작업 디렉터리의 점유 파일을 저장하지 못하면 Worker가 메모리에 남은 점유 ID로 `input-failed`를 보고하는 경로를 추가했습니다. 실패 보고까지 확인되지 않으면 작업 ID를 오류에 남기고 자동 재대기시키지 않습니다. Python 테스트에서 두 경로를 재현했고 Worker 테스트 32개가 통과했습니다. 실제 디스크 장애와 백엔드 장애가 동시에 발생한 환경은 검증하지 않았습니다.

2026-11-19 Worker 결과 분류 검증: `process-next`가 대기 작업 없음과 완료를 각각 반환하고, 백엔드가 입력·처리 실패를 `QUEUED` 또는 `FAILED`로 확인했을 때만 별도 예외로 구분하도록 했습니다. 점유 응답·실패 보고·heartbeat·결과 업로드·완료 응답이 불확실한 경우는 확인된 실패로 취급하지 않습니다. Python 테스트 36개가 통과했습니다. 반복 실행 명령과 실제 GPU 자식 프로세스·OCI 연동 검증은 아직 없습니다.

2026-11-19 Worker 반복 실행 검증: `work-loop`가 작업 없음에는 5초 대기, 완료·확인된 실패에는 즉시 재조회, 현재 시도 상태가 불확실한 오류에는 중단하도록 구현했습니다. SIGTERM 처리 시 반복을 멈추고 기존 신호 처리기를 복원하는 경로를 테스트했습니다. Python 테스트 41개가 통과했습니다. 실제 GPU 하위 프로세스 종료, OCI 연동, 서로 다른 호스트 간 동시 실행 제한은 검증하지 않았습니다.

2026-11-19 MySQL 대기열 동시성 검증: 격리된 MySQL 8.4.13 DB에 Flyway 마이그레이션을 적용하고 백엔드 `verify`를 통과했습니다. 두 요청이 한 작업을 동시에 점유할 때 한 요청만 점유하고 시도 횟수가 한 번 증가했으며, 가장 오래된 행을 별도 트랜잭션이 잠근 동안 `claim-next`가 다음 작업을 선택한 뒤 잠금 해제 후 원래 작업을 선택함을 확인했습니다. MySQL 전용 테스트 2개가 모두 통과했습니다. 이는 `claim-next`의 DB 행 잠금 동작 검증이며, 전체 GPU 실행 수 제한이나 OCI·실제 GPU 처리 검증은 아닙니다. 재현 명령은 [백엔드 안내](../backend/README.md#mysql-대기열-동시성-테스트)에 있습니다.

2026-11-19 로컬 Worker 잠금 검증: 별도 Python 프로세스가 같은 `work-dir`의 잠금을 보유한 동안 `process-next`가 백엔드 `claim-next`를 호출하기 전에 중단됨을 확인했습니다. 잠금 해제 후 재획득도 확인했으며 Windows Python 3.14와 Linux 컨테이너 Python 3.11에서 Worker 테스트 42개가 각각 통과했습니다. 실제 GPU 하위 프로세스, 다른 작업 디렉터리·호스트 사이의 동시 실행 제한은 검증 범위에 포함되지 않습니다. 초기 배포에서는 [단일 Worker 운영 결정](decisions/0007-single-gpu-worker.md)을 적용합니다.
