# 0004 — 검수 승인 후 원본 영상 7일 보관

- 상태: 채택
- 날짜: 2026-11-12
- 근거: 사용자가 일반 매물 원본 영상의 삭제 정책으로 "검수 승인 후 7일 보관하고 삭제"를 선택함.

## 결정

일반 매물의 원본 영상은 모델·뷰어·이동 제한 검수를 승인한 시점부터 7일간 보관한 뒤 삭제합니다. 단순 학습 완료나 업로드 완료를 기준으로 삭제하지 않습니다. 최종 투어 모델·충돌 데이터·미리보기는 이 원본 삭제 정책의 대상이 아닙니다.

동의를 받아 별도 지정한 캡스톤 평가용 데이터는 일반 매물 원본과 구분해 보관합니다. 모든 서비스 원본을 자동으로 평가 데이터로 전환하지 않습니다. 평가용 자료의 구체적인 보관 기간·위치는 별도로 정합니다.

삭제 후 원본에서 재학습하려면 재업로드가 필요할 수 있다는 점을 등록자에게 안내합니다. 학습 완료만으로 정확한 공간이나 재처리 가능성이 보장되는 것은 아닙니다.

## 구현 시 반영할 사항

백엔드가 검수 승인 시각과 삭제 예정 시각을 관리하고 정기 작업이 기한에 도달한 원본을 삭제하는 방식을 제안합니다. 검수가 취소된 경우와 해당 원본을 사용하는 재처리 작업이 있는 경우에는 삭제 조건을 재확인해야 합니다. 삭제 성공·실패를 기록하고 실패는 재시도합니다. 삭제 상태를 DB에 표시했다고 실제 파일 삭제가 완료된 것으로 처리하지 않습니다.

Oracle Lifecycle은 객체의 마지막 수정 시각 기준이므로 업로드 후 7일 삭제 규칙으로 이 정책을 대체하지 않습니다. 버전 관리가 켜져 있으면 이전 버전까지 확인해야 실제 용량 정리가 됩니다. Worker의 로컬 복사본과 프레임·체크포인트 등 중간 산출물도 존재할 수 있으므로 별도 정리 범위를 정의해야 합니다. 이 문서는 그 자료의 일괄 삭제를 승인한 기록은 아닙니다.

공식 근거 (2026-11-12 확인): [OCI Object Lifecycle Management](https://docs.oracle.com/en-us/iaas/Content/Object/Tasks/usinglifecyclepolicies.htm).

## 영향

원본이 계속 누적되는 것을 줄이고 제한된 스토리지 용량을 확보합니다. 이미 무료 범위 안에서 운영 중이라면 당장의 청구액 절감보다는 용량 확보 효과가 큽니다. 재촬영·재업로드·재학습 부담과 복구 가능성의 감소를 함께 고려합니다.

현재는 정책과 구현 방향만 기록했습니다. 실제 객체 삭제나 자동 삭제 설정은 수행하지 않았습니다.
