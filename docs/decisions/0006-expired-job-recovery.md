# 0006 — 만료 작업은 이전 실행 확인 후 수동 복구

- 상태: 채택
- 날짜: 2026-11-19
- 근거: Worker의 heartbeat와 로컬 프로세스 감시는 직접 실행한 프로세스만 추적합니다. 점유 만료나 Worker 중단만으로 GPU 계산의 종료를 확인할 수 없습니다.

## 문제와 선택지

만료된 `PROCESSING` 작업을 바로 재대기시키거나 지정 작업 `claim`으로 새 점유를 발급하면 이전 GPU 실행과 새 실행이 겹칠 수 있습니다. 만료만으로 즉시 `FAILED` 처리하면 일시적인 Worker 장애 후 재시도 기회를 잃습니다.

## 결정

만료된 작업의 자동 재점유를 막고 `PROCESSING`에 둡니다. 운영자가 이전 실행의 종료·취소를 확인했을 때만 별도 복구 토큰으로 `recover-expired`를 호출합니다. 백엔드는 기존 점유 ID, 만료 시각, `previousExecutionStopped: true` 선언을 검사하고, 남은 시도와 `retryable`에 따라 `QUEUED` 또는 `FAILED`로 전환합니다. 기존 결과 쓰기 권한을 회수하고 결과 키를 비워 이전 시도의 산출물이 새 시도의 결과가 되지 않게 합니다.

## 영향과 재검토 조건

복구 확인 전까지 작업이 `PROCESSING`에 남는 운영 부담이 있습니다. 백엔드는 GPU 프로세스 종료를 직접 증명하지 못하므로 선언이 사실인지 확인하는 책임은 운영자에게 있습니다. GPU 실행 ID를 저장하고 공급자 API로 실행 조회·취소를 검증할 수 있게 되면 자동 복구 범위를 다시 검토합니다. 현재 API와 제한은 [서비스 간 계약](../../contracts/README.md#영상ply-전송)에 있습니다.
