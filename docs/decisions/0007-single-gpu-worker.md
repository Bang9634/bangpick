# 0007 — 초기 GPU 서버는 Worker 한 개와 고정 작업 디렉터리 사용

- 상태: 채택
- 날짜: 2026-11-19
- 근거: 초기 배포에 GPU 한 대를 사용한다는 사용자 선택. 현재 `claim-next`는 서로 다른 작업을 여러 Worker에 줄 수 있고, 로컬 잠금은 같은 호스트·같은 작업 디렉터리에서만 작동한다.

## 문제와 선택지

DB의 중복 점유 방지는 같은 작업을 두 번 실행하지 않게 하지만, 다른 작업 두 건이 GPU 한 대에서 동시에 실행되는 것은 제한하지 않는다. 초기부터 백엔드에 전역 GPU 슬롯을 만들거나, GPU 서버당 Worker 실행 수를 하나로 제한할 수 있다.

## 결정

초기 GPU 서버에서는 `work-loop` 프로세스를 하나만 실행하고, 재시작 후에도 같은 영속 작업 디렉터리를 사용한다. 같은 서버에서 수동 처리 명령을 실행할 때도 이 디렉터리를 사용한다. 기존 파일 잠금은 같은 디렉터리를 쓰는 두 프로세스가 동시에 작업을 점유·처리하지 않도록 막는 보조 장치다. 배포 절차와 현재 컨테이너의 한계는 [인프라 안내](../../infra/README.md#worker-컨테이너)에 둔다.

백엔드에 전역 실행 슬롯은 추가하지 않는다. 처리 명령은 자신이 시작한 GPU 하위 프로세스가 끝나거나 중단될 때까지 기다린 뒤 종료해야 한다. 점유 만료와 파일 잠금 해제는 분리된 GPU 프로세스의 종료를 증명하지 않는다.

## 영향과 재검토 조건

서로 다른 작업 디렉터리나 호스트를 쓰는 Worker는 이 잠금을 공유하지 않는다. 같은 디렉터리에서도 유휴 상태의 `work-loop` 프로세스 두 개가 존재할 수 있으므로 배포에서 인스턴스 수를 하나로 유지해야 한다. GPU를 여러 대로 늘리거나 여러 Worker가 한 GPU를 공유해야 하면 슬롯 할당 방식과 중복 실행 방지를 다시 설계한다.
